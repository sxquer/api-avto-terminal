# API: статус оплаты из 1С

1С передает агрегированный статус счетов по VIN. Backend обрабатывает только сделки основной воронки amoCRM `7523034`.

## Основной endpoint

```http
POST /api/amocrm/integrations/1c/payments/status
Authorization: Bearer <SANCTUM_TOKEN>
Content-Type: application/json
Accept: application/json
```

```json
{
  "vin": "JTDBR32E720123456",
  "status": "paid"
}
```

- `vin` — обязательная строка до 64 символов;
- `status` — обязательное значение `paid` или `unpaid`.

## Переходный legacy endpoint

```http
POST /api/amocrm/integrations/1c/payments/paid
```

Адрес временно сохранен, чтобы не ломать существующую интеграцию:

- VIN без `status` трактуется как `paid`;
- при переданном `status` поддерживаются `paid` и `unpaid`;
- новым клиентам следует использовать `/payments/status`.

## Логика

### `unpaid`

- `Счёт выставлен (Усс)` (`990217`) = `true`;
- `Счёт оплачен (Усс)` (`990219`) = `false`;
- `Цвет сделки` (`974799`) = `Красный` (`1231087`);
- стадия не меняется, даже если карточка уже находится на этапе `Оплачено`.

### `paid`

- `Счёт выставлен (Усс)` (`990217`) = `true`;
- `Счёт оплачен (Усс)` (`990219`) = `true`;
- `Цвет сделки` (`974799`) = `Зеленый` (`1231089`);
- открытая сделка переводится на этап `Оплачено` (`64577710`);
- закрытые стадии `142` и `143` не переоткрываются, но checkbox и цвет обновляются.

Оплата является приоритетным источником поля `Цвет сделки`: последнее событие `paid/unpaid` может перезаписать цвет, ранее установленный логикой ДТ.

## Успешный ответ

```json
{
  "message": "OK"
}
```

Повторная отправка безопасна: backend обновляет только отличающиеся поля и не переводит сделку повторно на тот же этап.

## Ограничения

Сделки из воронок `Транзит по РФ` (`10944982`) и `Офис Москва` (`11036918`) не изменяются. Для них возвращается HTTP `409`.

Если один VIN найден в нескольких сделках подключенных воронок, API также возвращает `409` и ничего не меняет.

## Ошибки

| HTTP | Когда возвращается |
|---:|---|
| `401` | Bearer-токен отсутствует или неверен |
| `404` | Сделка с VIN не найдена |
| `409` | Несколько сделок с VIN либо сделка не в основной воронке |
| `422` | Нет `vin`/`status`, неверный тип или неподдерживаемый `status` |
| `502` | amoCRM не ответила или не приняла обновление |

## Настройки

```dotenv
ONEC_PAYMENT_PIPELINE_ID=7523034
ONEC_PAID_STATUS_ID=64577710
```
