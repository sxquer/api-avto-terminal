POST /api/amocrm/td-status POST /api/amocrm/dt-status Новых endpoint нет Пока не закоммичено и не развёрнуто
До live-проверки: изменения нужно закоммитить и развернуть, сбросить кэш конфигурации Laravel и убедиться, что AMOCRM_TEST_MODE=false. Сейчас код находится только в локальной рабочей копии.

Что конкретно изменено сегодня

1. Поиск сделки по VIN

Раньше поиск выполнялся только в основной воронке. Теперь он охватывает три воронки:

  • Основная — 7523034;
  • Транзит по РФ — 10944982;
  • Офис Москва — 11036918.

Если одинаковый VIN найден более чем в одной подключённой сделке, API возвращает ошибку до изменения полей и этапов.

2. Маршрутизация по воронке

После поиска учитывается, в какой воронке находится сделка. Один и тот же входящий статус больше не применяется одинаково ко всем карточкам.

  • td-status работает для основной и транзитной воронок;
  • dt-status работает для основной и «Офис Москва»;
  • нерелевантные для воронки события отвечают 200 OK, но ничего не меняют.

3. Защита от откатов

  • ТД Зарегистрирована не открывает повторно транзит, уже находящийся на этапе «закрыт»;
  • регистрация ПТД не возвращает сделку «Офис Москва» с выпуска назад на ПТД/ТД;
  • если сделка уже на целевом этапе, повторная команда смены этапа в amoCRM не отправляется.

4. Что не менялось

  • форматы запросов и имена полей tdNum/pdNum;
  • Bearer-аутентификация;
  • старая логика основной воронки;
  • передача «Транзит завершен» точным текстом без enum ID;
  • коррекция входящего времени UTC+10 → UTC.

Подготовка к live-прогону

  • Использовать две отдельные тестовые сделки с реальными уникальными VIN.
  • Проверить, что этих VIN нет в других сделках трёх подключённых воронок.
  • Зафиксировать этапы и значения полей до теста скриншотом.
  • Подставить боевой адрес API вместо https://<API_HOST> и действующий Bearer-токен.
  • Не использовать один VIN одновременно для обоих сценариев.

В интерфейсе amoCRM ожидаем дату и время из запроса. В API дата сохраняется с действующей внутренней коррекцией −10 часов.

Live-тест 1. Закрытие транзита по РФ

Исходное состояние сделки

  1. Воронка: Транзит по РФ — ID 10944982.
  2. Этап: Транзит по РФ (открыт) — ID 86060670.
  3. У сделки заполнен уникальный VIN; этот VIN подставить вместо <VIN_TRANSIT>.
  4. Желательно заранее заполнить номер ТД, чтобы убедиться, что при завершении он не перезаписывается.

Запрос

curl -X POST 'https://<API_HOST>/api/amocrm/td-status' \
  -H 'Authorization: Bearer <TOKEN>' \
  -H 'Content-Type: application/json' \
  --data-raw '{
    "vinNum": "<VIN_TRANSIT>",
    "tdNum": "LIVE-TD-20260720-01",
    "status": "Транзит завершен",
    "statusDate": "2026-07-20 15:30:00"
  }'

Ожидаемый результат

  • HTTP 200 OK, тело {"message":"OK"}.
  • Этап сделки стал «Транзит по РФ (закрыт)» — ID 86372326.
  • «Статус ТД» (поле 984685) = Транзит завершен.
  • «Дата и время завершения ТТ» (поле 990795) = 20.07.2026 15:30 в интерфейсе amoCRM.
  • Номер ТД и дата регистрации ТД не изменились.
Дополнительная защита: после успешного закрытия можно отправить для того же VIN статус ТД Зарегистрирована. Ответ останется 200 OK, но этап должен остаться «закрыт», а поля не должны откатиться на регистрацию.

Live-тест 2. Выпуск в «Офис Москва»

Исходное состояние сделки

  1. Воронка: Офис Москва — ID 11036918.
  2. Этап: ПТД/ТД — ID 86718954.
  3. У сделки заполнен другой уникальный VIN; его подставить вместо <VIN_MOSCOW>.

Запрос

curl -X POST 'https://<API_HOST>/api/amocrm/dt-status' \
  -H 'Authorization: Bearer <TOKEN>' \
  -H 'Content-Type: application/json' \
  --data-raw '{
    "vinNum": "<VIN_MOSCOW>",
    "pdNum": "LIVE-PD-20260720-02",
    "status": "выпуск с уплатой",
    "statusDate": "2026-07-20 16:00:00"
  }'

Ожидаемый результат

  • HTTP 200 OK, тело {"message":"OK"}.
  • Этап сделки стал «Выпуск по ПТД/ДТ» — ID 86718958.
  • «Номер ДТ» (поле 979423) = LIVE-PD-20260720-02.
  • «Статус ДТ» (поле 979425) = выпуск с уплатой (32).
  • «Дата выпуска ДТ» (поле 979429) = 20.07.2026 16:00 в интерфейсе amoCRM.
Дополнительная защита: после выпуска можно отправить для того же VIN статус регистрация ПТД. Ответ останется 200 OK, но сделка должна остаться на этапе «Выпуск по ПТД/ДТ», без отката полей на регистрацию.
